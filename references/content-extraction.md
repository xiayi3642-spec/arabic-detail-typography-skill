# 任意格式文案提取

本流程把任意粘贴内容编译成可排版的页面计划。它由调用 skill 的大模型执行，不由 HTML 正则解析器执行。

## 一、先理解内容，不猜格式

输入可能是自然语言、Markdown、表格、聊天记录、会议纪要、OCR 文本、中阿双语稿、旧版详情页文案或多种内容的拼接。标题、加粗、冒号、列名和换行都只是弱线索。

先从全文识别：

- 商品是什么，面向什么使用场景；
- 哪些是明确事实、参数、配件、功能和限制；
- 哪些是可以由事实直接支持的用户收益；
- 哪些只是设计要求、工作过程、疑问、备选稿或重复内容；
- 哪些信息相互冲突、缺少证据或仍待确认。

先保留原始数字、单位、数量、否定词和适用条件，再做压缩。不要因为排版需要而改变事实边界。

## 二、建立证据账本

在写标题前，先在内部整理以下四类信息：

| 类别 | 处理方式 |
|---|---|
| 已确认事实 | 可直接用于标题、副标题或卖点 |
| 事实支持的直接收益 | 可改写，但不得扩大承诺 |
| 待确认/冲突信息 | 标为 `needs_confirmation`，不作为确定文案 |
| 流程与设计备注 | 不进入消费者文案 |

每个最终卖点都应能回答“它来自原料中的哪条事实”。可在页面 JSON 中增加不参与渲染的 `source_evidence` 数组，保存简短中文证据摘要。

## 三、判断页面角色

不要依赖“模块一”“头图”等显式标签才判断页面：

- 总览商品身份、核心价值、适用场景，或内容位于整套文案最前且承担概括作用 → `hero`；
- 解释一个具体功能或结构带来的收益 → `feature`；
- 集中列参数、尺寸、材质或配件 → `spec`；
- 使用步骤、警示、清洁或维护 → `instruction`。

当前透明文字模板主要承载 `hero` 和 `feature`。高密度 `spec` / `instruction` 应压缩为单一重点，或留给更合适的高信息模板，不要硬塞小字。
普通 `feature` 页不得因原料中还有其他标签或事实，就沿用模板旧列表或自动追加底部详情列表；这些剩余信息要么压缩进副标题，要么留到真正的 `spec` / `instruction` 页。

若用户只提供一团未分模块的材料，默认生成 1 个 `hero`，再按互不重复的核心主题生成若干 `feature` 页；页面数量由信息量决定，不按原始段落数机械拆分。

## 四、首图固定提炼三个卖点

`hero-icons` 默认使用 3 个短卖点。选择顺序：

1. 最能区分商品的结构或核心能力；
2. 用户可直接感知的主要收益；
3. 使用、携带、安装、收纳或适用场景上的便利。

要求：

- 三项必须是不同信息，不能把同一事实同义改写三遍；
- 标签短、能独立读懂，避免“高品质”“方便实用”等无证据空话；
- 优先保留强事实，如数量、结构、操作方式、材质与明确配件；
- 可把功能改写成直接收益，但不能加入原料未承诺的效果；
- “禁写、缺失、暂不提供”的信息只用于排除错误文案，不单独生成消费者页面；例如“尺寸先不要写”不能变成“规格待确认”模块；
- 不跨越操作证据推导额外承诺；例如“侧面添柴”不自动等于“无需抬锅”“无需停火”或“不中断烹饪”；
- 只有两项可靠信息时，检查能否从其中一项得到保守且直接的体验收益；仍不足则记录缺口，不编造第三项。

示例：原料中出现“双层炉身、侧面添柴、各层可套叠放入网袋”，可提炼为“双层炉身 / 侧面添柴 / 套叠收纳”。不要扩写成“无烟燃烧 / 添柴不中断 / 一手即可携带”，除非材料明确支持。

## 五、生成排版文案

每页按以下顺序生成：

1. `zh_audit`：中文审核意，完整保留事实边界；
2. `title_lines`：一个结果导向的短标题，通常 1–2 行；
3. `subtitle_lines`：只解释主标题，不重复另一个卖点；
4. `highlights`：最多两个确实值得强调的短语；
5. 首图的 `icons`：默认恰好三个；
6. 阿语：根据中文审核意起草，未获确认时使用 `draft-needs-native-review`。

文案压缩顺序：删除空标签与修饰语 → 合并重复信息 → 保留动作、对象和结果 → 把次要信息移入副标题 → 必要时拆页。

排版容量是语义提取的硬约束：主标题最多 2 个视觉行，副标题最多 2 个视觉行。长副标题应先按语义压缩；若保留完整信息，则允许在阿语词间自然换为两行。不得把副标题强制为单行后交给预览容器裁切，也不得只审计主标题而跳过副标题。

## 六、交付前语义检查

- 每页是否只有一个核心信息？
- 首图三个卖点是否互不重复且均可回溯？
- 是否遗漏否定词、适用条件、单位、数量或配件关系？
- 是否把设计备注、内部讨论或疑问写进了消费者文案？
- 是否出现原料没有承诺的绝对化效果？
- `zh_audit` 是否足以让中文审核者发现翻译偏差？

语义检查通过后，才进入 JSON、HTML 和视觉溢出审计。
